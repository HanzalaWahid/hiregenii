# Security Review

**Scope:** Source-based review of the two current applications and their existing documentation. No remediation was performed. No live deployment, live Supabase project, production configuration, or runtime traffic was inspected. Severity is a prioritization assessment, not an exploitability guarantee.

| ID | Severity | Finding and source evidence | Impact | Recommended remediation |
|---|---|---|---|---|
| S-01 | P1 | **JWT sent in WebSocket query string and logged by frontend.** `Hire-geni/frontend/src/hooks/useJobUpdates.tsx` builds `/ws/jobs?token=${token}` and logs the full URL. Backend `Hire-geni/backend/main.py` accepts that query token. | Bearer token may be exposed to browser console, diagnostics, proxy/access logs, or copied URLs. | Avoid logging credential-bearing URLs; use a WebSocket authentication design that does not place bearer tokens in query strings where feasible; redact access logs and rotate/revoke exposed sessions. |
| S-02 | P1 | **Hire-geni original resume and removed PII are stored in SQLite; uploaded file is written to local disk.** `Hire-geni/backend/main.py` upload flow stores `original_text` and `removed` in `cv_records` and writes files under `UPLOAD_DIR`; no cleanup was observed in the inspected upload flow. | Sensitive resumes and identifying data can persist beyond the analysis/application need and may be exposed through local disk/database access or backups. | Define retention/deletion and access policies; store files privately with owner-scoped access; minimize stored raw/removed values and define encryption, backup, and cleanup practices. |
| S-03 | P1 | **No Supabase/RLS or organization-level isolation exists in the current implementation.** Current Hire-geni uses SQLite and route-level ownership checks; there are no organizations or tenant keys in `models.py`. | The proposed organization-oriented product has no current database tenant boundary; future multi-tenant access cannot rely on current model structure. | Before multi-tenant rollout, approve organization/membership design, enforce authorization in APIs and database RLS, and test cross-tenant access. |
| S-04 | P1 | **Analyzer API has no authentication/authorization.** `backend/app/api.py` declares analysis and mutable skill-mapping routes without auth dependencies. | Anyone able to reach the API can submit resumes and mutate in-memory skill aliases; no per-user quota or ownership boundary exists. | Decide whether public access is intended; otherwise add identity, authorization, abuse controls, and ownership-aware data handling before connecting to the unified product. |
| S-05 | P1 | **Hire-geni role/ownership checks are implemented inconsistently at route level.** Most recruiter operations use `_get_owned_job`; review needed around `GET /shortlisted`, interview endpoints, `GET /cv/{cv_id}`, reveal flows, and application route duplication. `GET /shortlisted` lacks an explicit recruiter-role guard (it filters jobs by caller id). | Future changes or inconsistent paths could expose data or permit actions outside intended role/ownership. This review did not prove a direct cross-user exploit in each route. | Centralize authorization policies; verify role and resource ownership on every route; add negative tests for other users, unrelated recruiters, and cross-organization access. |
| S-06 | P1 | **Hire-geni WebSocket authentication does not re-resolve an active user.** `/ws/jobs` decodes token, reads `uid`, and accepts the connection; `get_current_user` elsewhere resolves email and checks `is_active`. | A token whose user is disabled or otherwise no longer authorized may remain usable until expiry, depending on token validity and account lifecycle. | Reuse a consistent identity/active-account validation policy for WebSocket sessions and close connections when authorization is revoked. |
| S-07 | P2 | **No rate limiting is configured in inspected FastAPI applications.** Route definitions and middleware show CORS/GZip/timing but no limiter. | Login, upload, parsing, and AI-provider routes may be subject to brute-force or resource/cost abuse if publicly reachable. | Set deployment-layer and application-layer rate/size/concurrency limits appropriate to auth, upload, and provider cost. |
| S-08 | P2 | **Analyzer upload is copied before size validation.** `backend/app/api.py` copies the upload into a temporary directory before `validate_resume` applies configured maximum size. | Large request bodies can consume disk and processing resources before rejection. | Enforce streaming byte limits while receiving the upload and retain the post-save validation as defense in depth. |
| S-09 | P2 | **AI-provider processing sends extracted resume content externally when explicitly selected.** Analyzer Gemini/Cerebras extractors send `raw_text`; Hire-geni's LLM router sends prompts to Groq/Gemini when configured. | Resume PII may leave the application boundary without a visible consent/retention control in the inspected API flow. | Define provider-specific consent, minimization/redaction, retention, and contractual controls; document provider selection and failure behavior to users. |
| S-10 | P2 | **Hire-geni creates upload files under a local directory with no cleanup observed in the CV upload route.** Names are generated, extension/signature/size checked, but persistence lifecycle is unclear. | Disk accumulation and sensitive file exposure through server filesystem/backups. | Define private storage, retention, deletion, permissions, backup, and malware/content handling policies. |
| S-11 | P2 | **Hire-geni frontend stores JWT in `localStorage`.** `Hire-geni/frontend/src/lib/api.ts` reads/writes `auth_token`; `AuthContext.tsx` restores it. | Tokens are accessible to same-origin JavaScript and can be exfiltrated in an XSS event. | Evaluate an HttpOnly Secure SameSite cookie or another reviewed token strategy; apply CSP and XSS defenses; define CSRF controls if cookie-based. |
| S-12 | P2 | **Debug statements print account email and job payload to stdout.** `Hire-geni/backend/main.py` job creation route includes `current_user.email` and `payload.model_dump()`. | Logs can retain account identifiers and submitted business data beyond the request. | Remove debug prints; use structured, access-controlled logging with PII/data redaction and defined retention. |
| S-13 | P2 | **Unauthenticated bias-report route reads a local dataset and exposes aggregate metrics.** `GET /bias-report` has no auth dependency in `Hire-geni/backend/main.py`. | Exposes internal metrics and reports a simplified dataset measure as a bias signal; no verification/caveat is enforced by API. | Decide intended audience; protect if internal. Validate methodology and label uncertainty before using for hiring or compliance decisions. |
| S-14 | P3 | **Error and environment behavior needs production review.** Analyzer returns exception text in some 500 responses; Hire-geni startup migration catches broad exceptions around `ALTER TABLE` and token secret behavior differs between production and development. | Error detail may disclose internals; broad migration suppression can obscure schema drift; process-random development JWT secret invalidates sessions on restart. | Return stable sanitized errors; make migrations explicit and observable; document required production settings and fail startup on invalid production secrets. |
| S-15 | P3 | **CORS configuration is development-oriented and broad in methods/headers.** Both apps list localhost origins and allow all methods/headers for those origins. | Misconfiguration risk if production origins are added without review; CORS is not an authorization boundary. | Maintain an explicit environment-specific origin allowlist and test deployment configuration. |

## Authentication and JWT notes

Hire-geni passwords use PBKDF2-SHA256 through Passlib. JWT signing uses configured HS256/384/512; a weak/missing development secret is replaced with a random per-process value, while production requires a 32-character configured secret. The bearer-token dependency decodes token and resolves user by email, then checks active status. These are positive controls but do not replace route authorization, session revocation, secure token handling, or tenant isolation.

## RLS and Supabase status

No Supabase client, configuration, migrations, Edge Functions, or RLS policies were found in the inspected application code. The local `data/app.db` and `Hire-geni/backend/hr_platform.db` filenames do not establish the state of a live Supabase project. Live schema and deployment were not inspected.

## File upload and privacy notes

Hire-geni checks extension, size, PDF/DOCX signatures and UTF-8 for TXT; it uses generated names for stored PDF/DOCX files. The Analyzer validates extension, size, signatures, PDF integrity/text presence, and DOCX ZIP structure/macros, but copies the whole upload before size validation. Neither app's inspected path establishes malware scanning, private managed storage, deletion guarantees, or production backup protection.

## Recommended next review

Before production or unification, conduct an environment-aware security assessment with approved access, verify route-level authorization using negative tests, inspect deployed proxy/log settings and storage permissions, establish data lifecycle and provider-consent policies, and design Supabase RLS against an approved organization model. This document does not claim penetration testing or live configuration verification.
